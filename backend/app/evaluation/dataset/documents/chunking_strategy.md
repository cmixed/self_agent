# 文本切分策略与检索质量

文本切分（chunking）把长文档切成若干片段，片段是检索与向量化的基本单位。切分粒度会
显著影响检索质量，是 RAG 系统中最容易被低估的环节。

**块过大**时，一个片段里混合了多个主题，检索命中后会把大量**无关**内容一并送入模型，
既增加噪声又抬高上下文成本。**块过小**时，片段丢失了必要的上下文，模型难以据此作出
完整判断，召回结果也更容易碎片化。

工程实践中常见的取值是：chunk size 控制在 500 到 1000 个字符，块与块之间的重叠
（overlap）取块大小的 10% 到 20%，用来缓解跨块语义被切断的问题。

评估切分策略时，除了观察下游回答质量，还可以直接度量检索指标：命中率（Hit Rate）
衡量前 k 条结果中是否包含正确来源，Top-K 相关性衡量结果与问题的匹配程度，
来源对应性则检查最终回答引用的内容是否确实来自被检索到的片段。
